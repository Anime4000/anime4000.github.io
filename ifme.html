Why it exists

Before OBS, game recording meant FRAPS. FRAPS saved nearly raw video, so a few minutes of play filled gigabytes. I wanted to keep those recordings for nostalgia and rewatch them years later, without buying a new hard disk every month. So I wrote a small window in front of x264 to make them smaller.

The name comes from IF, a character from Hyperdimension Neptunia. It was going to be IF Media Encoder, but that artwork belongs to someone else. So IF became Internet Friendly — which is what it does: compress media for delivery over the internet.

It has outgrown that first job. IFME now remuxes, merges and repackages streams, keeps subtitles and fonts, and batches whole collections.

Eight interfaces ／ 使いやすさ

Set the whole queue once

The early interfaces were odd. Every time people told me where they got lost, the interface changed — eight times in all. Version 8 is the last one, because it finally meets the aim: you know what to do without asking, and without opening the documentation.

In HandBrake you apply settings to each item in the queue, one at a time. In IFME you select them all and set them once.

Every sub-stream follows suit, so the whole batch comes out in harmony. It plays anywhere, and Jellyfin can simply remux it instead of transcoding.

That is what people tell me they love about IFME: it is simple, and it is quick.

Architecture ／ 仕組み

Encoders are plugins

IFME does not build any encoder in. Each one is an outside program described by a small JSON manifest in the Plugins folder, so you can update it, swap it or add a new one without waiting for an IFME release.

That means you can compile an encoder for your own CPU with -march and -mtune and get every bit of speed from it. Compiling FFmpeg takes a long time; you do not need to. Compile x265, drop it in, and enjoy.

x265 tuned for your own CPU ／ 自分専用

cd x265/build/linux
cmake ../../source \
  -DCMAKE_C_FLAGS="-march=native -mtune=native" \
  -DCMAKE_CXX_FLAGS="-march=native -mtune=native"
make -j"$(nproc)"
# then copy the new x265 over the one in IFME's Plugins folder

On Windows, build it the same way in an MSYS2 shell from build/msys with -G "MSYS Makefiles".

Self-taught ／ 独学

Learned by building it

Nobody taught me any of this. IFME started in VB.NET, moved to C# for 4.0, and IFME 9 is C and C++ with Qt.

Every language, every tool, learned because IFME needed it.

Along the way: Makefiles, then CMake. Inno Setup installers. Mono, to run on Linux. FFmpeg, x264 and x265 built from source. And plenty of mistakes — for years I read FFmpeg's exit codes wrong, because I tried to work them out alone instead of asking.

I understand that I'm not a professional programmer, but I've done my best.

From the release notes of IFME 8.0 beta 1, 2022.
