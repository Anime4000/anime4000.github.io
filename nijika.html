What NIJIKA is

A GPON SFP stick is a whole ONT folded into a module: a Realtek SoC, a laser and a small Linux. The vendor firmware works, but it hides what the OLT is doing, speaks to few OLTs, and leaves you guessing when the line is up and the traffic is not.

NIJIKA is that firmware opened up. The classic line lives in the Firmware_Mod folder of RTL960x: an overlay of the stick's root filesystem, one folder per model, with the web pages, boot scripts and OMCI settings I changed. You unpack the stock image, lay the overlay on top and rebuild it.

NIJIKA-Luna, in 2026, goes further: the vendor's userland is gone, and the stick runs an open base from the bootloader up.

Under the hood ／ 改造

How the classic firmware is made

Each folder in Firmware_Mod mirrors the root filesystem of one stick: etc/ for the boot and OMCI settings, home/httpd/ for the web server and its pages. To mod an image, run qemu-test.sh, copy in what you need, and exit; the firmware images are rebuilt on the way out.

To change one file on a live stick there is no need to reflash. Listen with nc -l -p 12345 > file on the stick, send it with nc 192.168.1.1 12345 < file from a PC, then press Ctrl+C in the stick's telnet session, since its nc does not exit by itself.

NIJIKA-Luna ／ ルナ

A new base, the same Nijika

The classic firmware could only ever be as open as the vendor userland under it. Luna replaces that userland with ODI OSS: Linux 6.18 and open switch, GPON and OMCI drivers. Then it puts the Nijika parts back on top.

  • nijika CLI — the quick CLI, rewritten in C: ONT identity presets, the boot slot, the host SerDes and the OMCI presentation.
  • ONT presets — the classic numbering is kept, and the Huawei HG8240H is the new default.
  • Nijika UI — a LuCI-style web UI that draws the line, the services and the OMCI topology, and says what each change costs before you save it.
  • Safe upgrades — new firmware boots on trial first and falls back by itself if it does not come up.
